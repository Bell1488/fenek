# Fenek.pro — сайт и отправка заявок

Сайт запускается обычным Python-сервером. Для постоянной работы на VPS предусмотрены Gunicorn, Nginx и systemd.

## Уже настроено

- Главная страница, карго с калькулятором, короткие формы и реквизиты ООО «Фенек».
- Telegram менеджера: https://t.me/obmen_FENEK.
- Bot token, чат `-1004284976306` и socks5h-прокси записаны в **серверный `.env`**. Не переносите этот файл в `dist`.
- Фавикон Fenek: SVG, ICO (16/32/48/64 px), PNG 32 px и Apple Touch Icon 180 px.
- События Яндекс Метрики, UTM/yclid и инструкция `docs/YANDEX-DIRECT.md`.

## Осталось заполнить

1. Прокси уже записан в `.env`. Проверьте его с сервера: `python3 scripts/check-telegram.py`. Команда проверяет доступ к боту и чату, не отправляя сообщения. Без рабочего прокси отправка заблокирована; прямого обхода нет.
2. Счётчик `113930499` задан в `dist/config.js`. Создайте цели по инструкции.
3. Проверьте ссылку MAX — она сохранена с предыдущей версии. Telegram уже заменён на @obmen_FENEK.
4. Бот должен быть добавлен в указанный чат и иметь право отправлять сообщения.

## Самый простой локальный запуск

Нужны Python 3.10+ и системный curl с SOCKS/TLS.

```
./start-local.sh
```

Откройте `http://127.0.0.1:8080`. На Windows можно запустить `python backend/server.py`, предварительно задав локальные `ALLOWED_ORIGINS` и путь базы (ниже). Открытие HTML через `file://` подходит только для просмотра оформления, отправка так не работает.

Скрипт start-local.sh задаёт локальные разрешённые адреса, хранение базы в `private/` рядом с проектом и отключает доверие к заголовкам прокси для локального просмотра. Бот и SOCKS читаются из `.env`. Реальная отправка требует доступности настроенного SOCKS с вашего сервера.

Если запускаете вручную на Windows, в `.env` временно задайте:

```
ALLOWED_ORIGINS=http://127.0.0.1:8080,http://localhost:8080
LEAD_DB_PATH=private/leads.sqlite3
TRUST_REVERSE_PROXY=0
```

Перед размещением на сервере верните производственные адреса Fenek.pro и серверный путь базы.

## Размещение на VPS: Ubuntu/Debian

Нужны сервер, домен Fenek.pro с настроенной DNS и HTTPS. Команды ниже предназначены для вашего сервера, они не выполнялись автоматически.

1. Установите зависимости:

```
apt update
apt install python3 python3-venv curl nginx unzip
```

2. Разместите проект как `/opt/fenek` и создайте папку закрытой базы (команды выполняются от root):

```
mkdir -p /opt/fenek/private
chmod 700 /opt/fenek/private
```

При установке из Git создайте `/opt/fenek/.env` на VPS по образцу `.env.example` и заполните актуальными реквизитами бота, чата и SOCKS-прокси. Этот файл исключён из Git. Не рассчитывайте на `.env` в архиве или клоне. Службы работают от root, как и команды в этой инструкции. Публичная папка — исключительно `dist`, корень проекта с `.env` не должен раздаваться веб-сервером. Подробная инструкция: [`docs/DEPLOY.md`](docs/DEPLOY.md).

3. Создайте окружение и установите Gunicorn:

```
cd /opt/fenek
./scripts/install-venv.sh
```

4. Установите службы:

```
cp docs/fenek.service docs/fenek-cleanup.service docs/fenek-cleanup.timer /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now fenek.service fenek-cleanup.timer
systemctl status fenek.service
```

Служба слушает только `127.0.0.1:8080`, сама перезапускается при сбое. Почасовая служба очистки удаляет из серверной базы обращения старше 30 дней.

5. Подключите Nginx и сертификат SSL. Пример — `docs/nginx-fenek.conf`. Сначала получите сертификат для `fenek.pro` и `www.fenek.pro` вашим способом, затем установите конфигурацию с корректными путями к сертификатам и проверьте:

```
nginx -t
systemctl reload nginx
```

Nginx перенаправляет HTTP и www на `https://fenek.pro` и перезаписывает X-Real-IP. В `.env` доверие включено только для loopback-адресов локального Nginx. Если сервер размещается за другим прокси, явно настройте TRUSTED_PROXY_CIDRS и не доверяйте заголовкам произвольных посетителей.

6. Отправьте тестовую заявку с Fenek.pro и проверьте сообщение в чате. Затем проверьте Метрику и основную цель.

После изменения кода или `.env`:

```
systemctl restart fenek.service
```

Не используйте встроенный сервер Python для рекламного трафика. Для боевого сайта предназначена служба Gunicorn.

## Отправка и надёжность

Браузер → ваш HTTPS-сайт `/api/lead` → закрытая SQLite-база → **curl через socks5h** → Telegram Bot API. DNS имени Telegram также разрешается через SOCKS. При ошибке прокси прямого соединения нет. Секреты передаются curl через stdin, не через аргументы процесса.

Успех возвращается посетителю только после ответа Telegram `ok: true`. Ошибка, клик в мессенджер или локальное сохранение не считаются конверсией `lead_success`. Повтор доставленной заявки с тем же ID не создаёт второе сообщение. После неоднозначного таймаута повтор автоматически не выполняется, чтобы не продублировать уже принятое сообщение.

Для контроля недоставленных обращений:

```
cd /opt/fenek
.venv/bin/python backend/server.py pending
.venv/bin/python backend/server.py show UUID
```

Команда show выводит данные обращения — используйте её только в закрытой консоли администратора. Регулярно проверяйте недоставленные обращения. Автоматическая повторная отправка неопределённых заявок не включена.

## Файлы

- `dist/` — публичные страницы, стили, JS, изображения и favicon.ico.
- `.env` — серверные реквизиты бота, чата и SOCKS. Создаётся отдельно на VPS и не помещается в Git.
- `dist/config.js` — публичный номер Метрики и контакты менеджера. Секретов здесь нет.
- `backend/server.py` — API, валидация, база и обязательный socks5h.
- `start-local.sh` — локальный просмотр.
- `scripts/install-venv.sh` — установка окружения.
- `scripts/check-telegram.py` — проверка бота и чата через SOCKS без отправки сообщений.
- `docs/` — systemd, Nginx и настройка Директа.
- `tests/test_leads.py` — тесты, которые не отправляют реальные сообщения.

## Проверка

```
python3 -m unittest discover -s tests -v
```

Проверяются контакт, согласие, ограничения отправки, SOCKS с разрешением DNS на прокси, ошибки, защита от дублей и доступ к приватным файлам. Для работы заполните `.env` на VPS и запустите `python3 scripts/check-telegram.py`, затем проверьте доставку реальной заявкой с сайта. Тарифы калькулятора карго — ориентиры; подтвердите их перед рекламой.
